What's the best approach for structuring a Leptos app with multiple layout shells that share a sidebar but swap the center content? Looking for patterns that avoid full-page re-renders.

AI
Claude assistant
to #general
7:15 AM

In Leptos 0.8, the cleanest approach is nested routes with a shared layout component. Your outer route renders the sidebar + shell, and child routes swap the center panel:

<Route path="/app" view=AppShell> wraps the sidebar, then <Outlet/> in the center column renders whichever child route matches — inbox, conversation, run detail, etc. Only the <Outlet/> re-renders on navigation.

The sidebar stays mounted and reactive. If you need shared state across views (selected room, active run), use provide_context at the shell level.
